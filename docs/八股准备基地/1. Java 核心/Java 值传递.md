# Java 值传递

## 1. 大白话：这是什么？解决什么痛点？
Java 中**只有值传递**，没有引用传递！
用大白话解释，当你在 Java 中把一个变量作为参数传给方法时，Java 永远都是把这个变量复制一份**“分身（副本）”**递过去，**绝对不会把变量“原件”递过去**。
* **解决的痛点**：核心是为了**程序的安全和简单**。如果允许引用传递，外部方法就可以直接修改调用者底层的原始变量（比如直接把你的实参变量替换为 null 或重新赋值为其他对象），这会让数据变得不可控、极其危险，因此 Java 在语言设计之初就摒弃了这种复杂的指针/引用直接修改的特性。

## 2. 底层机制与高频考点
* **基本数据类型**：传递的是**实际数值的拷贝**。在方法内修改该参数，不会影响外部的实参原件。
* **引用数据类型（对象）**：传递的是**对象在堆内存中地址值的拷贝**。
* **高频考点（大厂最爱问）**：
  * **为什么修改属性会生效，而重新赋值（new）不会？**
    * 因为方法拿到的形参是“地址值的拷贝”。这就像是你复制了一把房子钥匙（地址拷贝）给别人。
    * 如果别人用这把钥匙进屋**打扫卫生或换个沙发（修改对象内部属性）**，等你回家时，屋子确实变了。
    * 但如果别人把这把钥匙给扔了，自己**又配了一把新别墅的钥匙（在方法内重新赋值形参，如 `param = new Object()`）**，这仅仅是让他手里的那把钥匙指向了别处，对你的房子（实参原对象和实参变量）没有任何影响。
  * **与 C++ 的对比**：
    * C++ 既支持值传递，也支持引用传递（通过 `&` 符号）。而 Java 只有值传递。

## 3. 🎯 实战口径
当面试官问“Java是值传递还是引用传递”时，可以直接这样回答：
> “**Java 中只有值传递，完全没有引用传递。**
>
> 无论是基本类型还是引用类型，方法接收到的都是**实参的一个副本**。
> 对于基本类型，拷贝的是具体的字面量值；对于引用类型，拷贝的是对象在堆中的**内存地址值**。
>
> 这就解释了为什么我们在方法内部**可以通过形参去修改对象的内部属性**（因为形参和实参指向同一个堆对象），但如果我们在方法内部**给形参重新赋值（比如 `param = new Object()`）**，这仅仅是改变了局部形参的指向，外部的实参变量完全不会受到影响。
>
> Java 这样设计，最核心的考量就是**安全性**，防止外部方法破坏或篡改调用方底层的核心变量引用。”
