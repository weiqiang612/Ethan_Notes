# 1. AI 应用开发面试总览（袁志刚专属版）

本指南基于您的苍穹外卖 AI Agent 客服系统（sky-ai）项目，系统梳理 AI 应用开发面试的三层考察体系，帮助您在面试中将 **通用 AI 理论** 与 **实际项目工程经验** 精准对接。

## 🎯 简历亮点总览：sky-ai 项目面试核心切入点

您的 sky-ai 项目是一个完整的 **AI Agent 客服调度系统**，面试官可以从以下任何一个点切入，展开深度追问：

### 1. Spring AI Advisor 链式调度管道
*   **面试官切入点**：
    > "你的 AI Agent 调度管道基于 Spring AI Advisor 链实现，请详细说明这条链路中每个 Advisor 的职责、执行顺序和数据流转方式。"
*   **核心组件映射**：
    | 执行顺序 | Advisor 组件 | 核心职责 | Order 优先级 |
    | :--- | :--- | :--- | :--- |
    | 1 | `IntentRecognitionAdvisor` | 意图识别（12 种意图分类） | `HIGHEST_PRECEDENCE` |
    | 2 | `UserContextAdvisor` | 用户画像记忆注入 + 动态工具白名单生成 | `HIGHEST_PRECEDENCE + 1` |
    | 3 | `RagAdvisor` | FAQ 知识库检索增强 | `HIGHEST_PRECEDENCE + 3` |
    | 4 | `ToolFilterAdvisor` | 动态工具过滤与注册（基于白名单） | `HIGHEST_PRECEDENCE + 4` |
    | 5 | `SafeToolCallAdvisor` | 工具调用死循环熔断（签名检测 + 轮次限制） | `LOWEST_PRECEDENCE - 100` |

### 2. 意图识别驱动的多步任务编排
*   **面试官切入点**：
    > "你提到了 12 种意图分类和动态工具白名单，请问你是如何根据不同意图来精准控制 Agent 能够调用的工具集的？"
*   **核心设计**：
    *   `IntentType` 枚举定义了 12 种客服场景意图：`ORDER_STATUS`、`TRACK_DELIVERY`、`CANCEL_ORDER`、`REQUEST_REFUND`、`MENU_QUERY`、`CART_MANAGEMENT`、`ADDRESS_MANAGEMENT`、`CHANGE_ADDRESS`、`REPORT_MISSING_ITEM`、`REORDER`、`SHOP_STATUS`、`ESCALATE_TO_HUMAN`、`FAQ`、`OTHER`。
    *   每种意图对应 **二级工具授权**：先按 `domain()`（ORDER/MENU/ADDRESS/SHOP）获取基础工具集，再按具体意图追加专属工具。
    *   例如：`CART_MANAGEMENT` 意图 = MENU 域基础工具（`searchDishes`、`searchSetmeals`）+ 购物车专属工具（`searchCartItems`、`listCart`、`addDishToCart`、`addSetmealToCart`、`removeCartItem`、`cleanCart`），共 8 个工具。

### 3. 用户记忆系统与个性化服务
*   **面试官切入点**：
    > "你的 Agent 如何实现用户画像的持久化记忆？不同意图场景下的记忆注入粒度是如何控制的？"
*   **核心设计**：
    *   `UserMemoryFactService` 管理 6 种用户记忆维度：`FAVORITE_DISHES`（偏好菜品）、`FAVORITE_FLAVORS`（口味偏好）、`DIETARY_RESTRICTIONS`（饮食禁忌）、`DEFAULT_ADDRESS`（默认地址）、`OPERATIONAL_NOTES`（运营备注）、`USER_PROFILE_NOTES`（用户画像摘要）。
    *   `ProfileInjectionLevel` 三级注入粒度：`NONE`（不注入，如查店铺状态）→ `SUMMARY`（摘要注入，如查订单）→ `FULL`（完整注入，如菜单浏览/购物车管理）。
    *   记忆不仅在对话上下文中注入，还在意图识别阶段就参与（`IntentRecognitionAdvisor` 将用户画像摘要拼接到用户消息前，提升意图识别精度）。

## 🚀 AI 应用开发面试三层考察体系

### 第一层：大模型基础认知（所有岗位必考）
*   Token 是什么？为什么中文、英文、代码消耗的 Token 不一样？
*   上下文窗口有什么限制？长上下文为什么不一定更好？
*   Temperature、Top-P、Top-K 分别控制什么？生产环境怎么调？
*   大模型为什么会产生幻觉？有哪些工程缓解方式？
*   JSON Mode、Structured Outputs、Function Calling 有什么区别？

### 第二层：AI 应用组件能力（拉开差距的关键）
*   RAG 召回率低怎么排查？是 Chunk 问题、Embedding 问题，还是排序问题？
*   Hybrid Search、Query Rewrite、Rerank 分别解决什么问题？
*   Agent Loop 是什么？和普通工作流有什么区别？
*   Agent Memory 怎么设计？短期记忆和长期记忆怎么区分？
*   MCP 和 Function Calling 有什么区别？生产级 MCP Server 怎么做安全治理？
*   Prompt Engineering 和 Context Engineering 到底差在哪？

### 第三层：AI 系统设计（社招和有项目经验者必问）
*   如何设计一个企业级 AI 知识库问答系统？
*   如何设计一个生产级 Agent 平台？
*   如何设计一个模型网关，支持限流、熔断、降级和成本统计？
*   如何设计 AI 应用评测体系？Golden Set、LLM-as-Judge、Trace 回放怎么做？

## 🗺️ 建议复习路线

### 第一步：快速建立知识地图
先快速过一遍本文和后续 4 篇面试题的标题和结构，知道 AI 应用开发面试会问哪些方向。

### 第二步：回到原文补底层理解
遇到答不上来的题，按以下映射回到具体文件：
*   Token、上下文窗口、采样参数不清楚 → `2. 大模型基础与 API 工程.md`
*   Agent Loop、Memory、MCP 边界不清楚 → `3. AI Agent 与工具调用.md`
*   RAG 效果优化说不清楚 → `4. RAG 检索增强生成.md`
*   生产级 AI 应用架构说不清楚 → `5. AI 系统设计.md`

### 第三步：用"工程表达"组织答案
AI 面试答题推荐结构：
1.  **先解释概念**：一句话讲清楚它是什么。
2.  **再说明问题**：它在真实系统里会带来什么影响。
3.  **接着给方案**：生产环境怎么设计、排查、优化或治理。
4.  **最后讲边界**：什么场景适用，什么场景不适用。

## 📊 不同经验阶段复习重点

### 应届生和 0-1 年
*   **目标**：能把 AI 应用开发的基本链路讲清楚。
*   **重点**：大模型基础（Token、上下文窗口、结构化输出）、RAG 基本链路、Agent 基础概念、简单的系统模块划分。
*   **关键差异**：不需要讲出复杂的模型网关和灰度回放，但要表现出你知道 Demo 到生产之间有工程差距。

### 2-3 年
*   **目标**：从"知道链路"升级到"能定位问题、能做取舍"。
*   **重点**：API 调用链路（限流、重试、结构化输出失败处理）、RAG 按阶段排查问题、Agent Memory/MCP/Function Calling 的边界与组合方式。
*   **关键追问**：知识库更新后旧答案还在怎么办？工具调用失败怎么降级？如何证明新 Prompt 比旧 Prompt 更好？

### 3 年以上
*   **目标**：能讲完整架构、治理策略和演进路线。
*   **重点**：架构设计（入口层→编排层→Prompt/Context→RAG→Memory→Tool→模型网关→评测→安全合规）、治理能力（模型路由、fallback、Token 成本归因、Prompt 版本管理）、质量闭环（Golden Set、Trace 回放、线上灰度、LLM-as-Judge）。
