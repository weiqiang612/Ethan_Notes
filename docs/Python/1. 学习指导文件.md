# Python Agent 工程能力提升计划（指导纲要）

## 定位

面向 Java 后端 + Spring AI 背景建立 Python Agent 工程能力。目标不是 Python 语法速成，也不是一开始就堆一个大项目。

最终作品方向为 **法律案件研究工作流 Agent（v1：劳动争议）**。它不冒充律师，也不是联网搜索后回答的 ChatBot；它把用户问题和材料转化为可持续维护的事实、证据、法律问题、来源、矛盾点、待办和研究备忘录。

## 学习与项目的关系

项目是能力验证场，不是教程载体。

    理解一个概念
      ↓
    独立小练习：自己实现、测试、复盘
      ↓
    迁移判断：它能解决法律研究工作流的哪个环节？
      ↓
    达到接入门槛后，才进入正式项目的一个小切片

- Week 1—2：通用 Python / 工程实验，不写正式法律项目。
- Week 3 起：按能力成熟度把已验证模块接入项目。
- 只有通过测试或可重复演示的模块，才能迁入项目。
- 不允许因为学习了框架就强行接入最终作品。

## 最终作品的差异化

通用 ChatBot 能上传文件、联网搜索和生成答案。作品的差异不在能不能搜，而在于把一次聊天固定成可核验、可恢复的研究任务：

    CaseResearchState
    ├── 事实时间线与待核实事实
    ├── 用户证据及其证明目的
    ├── 待研究法律问题
    ├── 已核验来源与引用关系
    ├── 矛盾、风险与不确定性
    └── 下一步研究动作 / 人工升级条件

完成标准是：有类型、测试、日志、异常与异步基础；理解原生 Tool Calling；能做可追溯检索和研究工作流；能对事实不足、错误引用、过期资料和敏感材料安全降级；最终交付一个诚实、可评测、可演示的作品。
