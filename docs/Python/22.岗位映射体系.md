# 岗位映射与求职适配体系

## 目标

把训练期间形成的代码、设计、评测和面试资产，转换成招聘市场可识别、可验证的能力表述。循环如下：

    JD
      → 提取能力要求
      → 映射已有证据与缺口
      → 调整 P0/P1 学习重点
      → 更新项目与简历表达
      → 面试反馈
      → 补强或修正证据

不要把“学过某个框架”当成匹配；只有代码、测试、设计记录或可讲清的实际经验才是证据。

## 一、目标岗位边界

| 方向 | 常见关键词 | 当前匹配 | 求职表达重点 |
| --- | --- | --- | --- |
| A：AI Agent 应用开发 | LangChain、LangGraph、RAG、Tool Calling、Agent Workflow、Python | 高 | 原生 Runtime、工作流、工具治理、RAG 路由、评测 |
| B：AI 后端开发 | Java/Python、Spring Boot/FastAPI、Redis、MySQL、API、模型接入 | 高 | Java 后端工程基础 + Python AI 应用生态 + 受控业务能力 |
| C：模型工程或算法 | Transformer、训练、微调、CUDA、PyTorch | 当前较低 | 不作为本训练周期主线，除非目标 JD 明确要求 |

对 A、B 方向，不说“我从 Java 转 Python”；推荐表达是：

> 我具备 Java 后端与 Spring AI 的工程经验，同时以 Python 构建 Agent Runtime、工作流和受控工具调用能力，能够完成业务服务到 Agent 能力层的开发。

## 二、能力—作品证据映射

| 招聘能力 | 对应训练周 | 最低证明材料 |
| --- | --- | --- |

| API 与后端边界 | Week 3 | FastAPI 接口、统一错误、依赖覆盖测试 |

## 三、JD 到行动的决策规则

每条 JD 关键词进入计划前问三件事：

1. 它能否进入最终“取消订单受控 Agent”作品？
2. 它是否高频出现在目标岗位的面试追问中？
3. 你能否在两周内留下可验证的证据？

三个答案中至少两个为“是”，才升级为当前 P0/P1；否则记录在 backlog，不为单个关键词打乱训练主线。

## 四、岗位材料存放

在实际训练仓库中建立：

    docs/interview/job-mapping/
    ├── README.md
    ├── {公司}-{岗位}-{日期}.md
    └── feedback-{公司}-{日期}.md

每个条目都使用 23 号文档模板，并链接真实 JD 原文或摘录。面试反馈用同一模板回写，形成下次投递的调整依据。
