## 一、Week 2 阶段定位

### 周目标

从“能运行确定性工具路由器”达到“能构建一个可测试、可扩展、可接入 API 层的 Agent Core”。本周不引入 LangChain；重点是 Python 工程能力、Agent Core 抽象与可靠性意识。

### 核心边界

```text
Router    → 选择工具
AgentCore → 管理状态、流程、异常转换与日志
Tool      → 执行具体能力
State     → 保存当前任务执行上下文
Observability → 记录可追踪、已脱敏的执行证据
Exception → 表达失败类型
```

### 本周核心产出

## Day 9：严格状态建模

### 今日目标

使用类型提示建立 Agent 任务状态，并明确 State 不是数据库实体。

### 学习输入

- Python `typing` 文档：`TypedDict`、`Literal`、`NotRequired`。
- 回顾 Week 1 的 dict 状态模型，识别字段与状态流转风险。

### 编码实践

在 `app/state.py` 定义：

```python
from typing import Literal, NotRequired, TypedDict

AgentStatus = Literal[
    "created", "running", "wait_confirm", "completed", "failed"
]

class AgentState(TypedDict):
    task_id: str
    intent: str
    params: dict[str, object]
    tool_name: NotRequired[str]
    result: NotRequired[dict[str, object] | None]
    status: AgentStatus
```

实现受控状态流转：`created → running → wait_confirm / completed / failed`。非法转换必须返回领域错误或失败结果，不允许静默覆盖。

### AI 辅助任务

> 请比较 Python TypedDict 与 Java DTO：类型安全、运行时校验、Agent 状态管理各有什么边界？哪些字段应进入任务 State，哪些不应放入？

### 验收检查

- 类型提示为什么不能替代运行时校验？
- 为什么 `result` 不是固定 `str`？
- State、数据库记录、长期 Memory 分别是什么？

### 当日产出

- 类型化 State 与状态转换测试。

## Day 10：异常体系与错误转换

### 今日目标

区分工具故障、策略/业务拒绝和未知系统错误，并将其转换成调用方可理解的结果。

### 学习输入

- Python 异常、异常链与 `raise ... from ...`。
- 不使用宽泛的 `except Exception: pass`；理解异常不能被吞掉。

### 编码实践

在 `app/exceptions.py` 分层定义：

- Tool：`ToolNotFoundError`、`ToolExecutionError`、`ToolTimeoutError`。
- Policy / Business：`PermissionDeniedError`、`ConfirmationRequiredError`、`InvalidOperationError`。

由 `AgentCore` 捕获已知异常，生成统一错误结果（任务 ID、错误码、用户可读信息）；未知异常记录完整上下文后重新抛出或转换为明确的内部错误，不伪装成成功。

### 验收检查

- 为什么“未确认取消订单”不是 ToolExecutionError？
- 工具超时后为何不能简单标记为“操作失败”？

| 范围 | 场景 | 预期 |

## Day 13：Async I/O 与受控并发

### 今日目标

### 学习输入

- Python `asyncio`：coroutine、task、`gather`、timeout。
- 对照 Java `CompletableFuture`：共同点是组合异步任务，差异是 Python 事件循环与阻塞调用风险。

### 编码实践

实现异步只读工具 `query_order()` 与 `query_user()`，并发执行后聚合结果。使用可控的模拟延迟和 timeout 测试；不要用真实第三方接口。

写操作保持串行，并在代码注释中说明：确认、权限、幂等和未知执行状态处理优先于并发优化。

## Day 14：Agent Core CLI 综合项目

### 今日目标

整合 Week 1–2 代码，交付一个可运行、可测试、具备安全边界的 Python Agent Core CLI。

### 架构

```text
User → AgentCore → Router → Tool → State Update
                         ↘ Exception Handler → Observability → Response
```

### 编码实践

完成三个能力：

- `query_order`：正常只读查询。
- `query_menu`：正常只读查询。
- `cancel_order`：只创建草稿与待确认任务，不直接执行。

取消订单返回：

```json
{
  "task_id": "xxx",
  "status": "wait_confirm",
  "confirmation_required": true,
  "draft": {
    "action": "cancel_order",
    "order_id": "123"
  }
}
```

职责必须保持：Router 仅将 intent 映射到工具；AgentCore 负责状态变化、异常转换、日志与流程控制；Tool 不直接承担路由或审计职责。

更新 README：架构、运行命令、测试命令、三条演示路径、已知限制与 Week 3 API 化计划。
