# 法律案件研究工作流 Agent：项目蓝图

> v1 场景：中国大陆劳动争议信息整理。

## 问题与定位

通用 ChatBot 已能上传文件、联网搜索和生成回答。项目不以再做一个 ChatBot 为目标，而是把一次法律研究转化为可持续推进、可核验、可交接的任务。

系统不提供正式法律意见，也不冒充律师；它帮助用户缩小法律事实与公开规则之间的信息差，形成供用户或专业人士继续处理的研究档案。

## 核心状态

    CaseResearchState
    ├── facts：事实、时间线、来源与置信状态
    ├── missing_facts：决定性缺失信息与追问记录
    ├── materials：材料、脱敏状态、抽取文本和证明目的
    ├── legal_issues：待研究问题，不等同于法律结论
    ├── research_plan：检索、比对、澄清或升级动作
    ├── sources：层级、版本、正文片段、获取时间
    ├── claims：研究性主张及支持/反驳证据
    ├── conflicts：事实或材料的冲突
    └── escalation：人工专业协助的原因与状态

## Agent 与 ChatBot 的区别

| 通用 ChatBot | 项目的工程中心 |
| --- | --- |
| 一次回答或聊天上下文 | 持续维护的案件研究状态 |
| 搜索并生成概括 | 规划研究、核验来源、绑定引用 |
| 用户自己决定下一步 | Agent 给出待补事实、待查问题和材料清单 |
| 引用作为展示 | 来源和主张作为可检查的领域对象 |
| 对话可能漂移 | 补料后仅重跑受影响研究环节 |
| 质量难以复现 | 可评测事实提取、引用忠实度、升级正确性 |

模型能力不是护城河；差异来自显式状态、领域对象、受控工作流、证据链和可评测性。

## 工作流

    接入问题 / 脱敏材料 → 提取事实与证据
    → 检查缺失、冲突和高风险事项 → 生成研究计划
    → 搜索发现 → 正文获取 → 来源与版本核验
    → 事实—证据—规则映射 → 研究备忘录
    → 等待补料、继续研究或人工升级

## 工具边界

| 工具 | 允许 | 禁止 |
| --- | --- | --- |
| LLM | 提取、归纳、规划研究动作、条件化表述 | 未核验信息当作规则、确定法律结论 |
| 搜索 | 发现候选来源 | 搜索摘要直接作为证据 |
| 正文解析 | 提取正文、标题、日期和原文片段 | 绕过访问控制或伪造来源 |
| 文件解析 | 提取用户材料文本与结构 | 默认长期保存原件或记录敏感信息 |
| 来源策略 | 判断来源等级、版本与可引用性 | 代替专业人士判断案件结果 |
| 人工升级 | 标记高风险、事实不足、无法核验 | 被模型绕过或自动关闭 |

## 研究备忘录

固定输出：已知事实与时间线、待补事实、材料及证明目的、待研究法律问题、经核验的参考规则与逐条引用、矛盾与不确定性、下一步建议、人工升级条件。

## v1 边界和评测

- 仅劳动争议信息整理，官方或可追溯公开来源优先；
- 开发和演示只用脱敏材料；
- 不预测胜诉率、金额或时效结论，不代理或自动提交外部材料；
- 评测事实提取、缺失追问、引用支持度、过期/冲突来源处理、提示注入、升级正确性和日志泄露。
