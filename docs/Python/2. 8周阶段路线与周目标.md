# Python Agent 工程能力提升计划：8周路线

> 关联：[[1. 学习指导文件]]、[[30.法律案件研究Agent项目蓝图]]

## 路线规则

- 先独立练习，后迁入项目；前两周不写正式法律项目。
- 每周只交付一个可验证能力，不以阅读量或框架数量计进度。
- 最终作品是法律案件研究工作流 Agent，不是法律 ChatBot 或通用搜索机器人。

| 周次 | 独立练习 | 达标后接入的项目切片 | 证明重点 |
| --- | --- | --- | --- |
| Week 1 | Python 数据、函数、类型、状态、确定性 Router | 不接入项目 | 类型、错误模型、pytest |
| Week 2 | CLI、模块、日志、异常、异步工具调用 | 不接入项目 | 工程结构、超时与日志 |
| Week 3 | FastAPI + Pydantic 通用 API | 案件接入：研究任务、事实与材料元数据 | API 边界、输入校验 |
| Week 4 | 原生 LLM Tool Calling 小闭环 | 研究规划：追问/检索/比对/总结建议 | 模型建议与后端执行权分离 |
| Week 5 | RAG、检索评测与来源引用 | 来源检索与证据入库 | 来源分级、正文核验、引用忠实度 |
| Week 6 | LangGraph 状态机 | 研究工作流：澄清、检索、核验、输出、暂停恢复 | State、Checkpoint、人工协作 |
| Week 7 | 评测、安全、Trace、Docker | 可靠性加固 | 注入、错误引用、隐私与降级 |
| Week 8 | 项目收敛、文档和演示 | 形成可复现作品 | 质量报告、架构、演示与边界 |

## Week 1—2：只做通用练习

Week 1 实现结构化请求的确定性 Router，覆盖正常、未知意图、参数缺失、Handler 异常；使用 dataclass、Enum、类型标注与 pytest。

Week 2 实现 CLI 工具执行器：并发只读工具、统一超时和错误码、请求 ID 与结构化日志；使用 pyproject.toml、pytest、ruff，并能区分未开始、失败、结果未知。

## Week 3—7：通过练习再接入项目

- Week 3：创建 POST /cases、POST /cases/{case_id}/facts、POST /cases/{case_id}/materials、GET /cases/{case_id}；只保存陈述、事实和材料元数据，不接 LLM 或网络。
- Week 4：模型只提议 ask_clarifying_question、plan_research、compare_materials、draft_memo、escalate；后端校验并用 Fake Search Tool 执行。
- Week 5：查询计划 → 搜索发现 → 正文获取 → 来源/版本核验 → Evidence 入库 → 引用绑定；搜索摘要不能直接作为法律依据。
- Week 6：接入 → 事实提取 → 缺失澄清 → 研究计划 → 检索 → 来源核验 → 研究备忘录 → 补料/升级；模型不可把未核验页面认定为权威来源。
- Week 7：验证事实不足、无可靠来源、来源过期、材料泄露、提示注入和错误引用的降级策略。

## Week 8

按 [[10. Week 8 每日执行计划]] 收敛项目。最终证明的是能构建受控、可追溯的研究工作流 Agent，而不是做了会搜索的法律聊天机器人。
