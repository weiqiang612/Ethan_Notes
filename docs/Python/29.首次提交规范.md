# 首次提交规范

## 目的

首次提交标记训练仓库的可信起点。它不是空目录打卡，而是已通过最小工具链验证的工程基线。

## 应包含的文件

- README.md；
- pyproject.toml 与 uv.lock；
- .gitignore；
- labs/week01-python-core/day01-env 的最小代码与测试；
- docs/learning-log/day00.md；
- docs/ai 的入口文档；
- 空目录需要通过 .gitkeep 或说明文件保留时，才加入版本控制。

## 不应包含的文件

- .venv；
- Python 缓存、pytest 缓存、ruff 缓存；
- API Key、.env 实际值、Token、真实用户数据和敏感日志；
- IDE 私人配置、本机绝对路径、构建产物。

## 提交前证据

将以下命令的实际结果写入 day00.md：

    uv run pytest
    uv run ruff check .
    uv run ruff format --check .
    git status

## 提交命令

    git add .
    git commit -m "docs: initialize python agent engineering roadmap"

若提交中同时包含 Day 0 的最小代码，仍使用该消息可以接受；重点是它建立工程路线与可运行基线。之后的 Day 1 代码使用更具体的 Conventional Commit，例如：

    feat(python-core): model tool router request state

## 提交后确认

    git log --oneline -1
    git status

应能看到提交信息且工作区干净。若不干净，先说明剩余文件的用途，再决定提交、忽略或删除；不进行盲目 git add。
