# 简历版本策略

## 原则

不使用一份简历投所有岗位。三个版本共享真实经历，但改变证据排序和项目讲法；任何版本都不能添加未验证技术、虚构指标或“生产可用”结论。

## Version A：AI Agent 开发版

**目标岗位**：Agent 应用开发、RAG、LangGraph、Python AI 工程。

**优先强调**：Python Agent Runtime、Tool Policy、RAG 路由、LangGraph 工作流、人工确认、Checkpoint、评测。

**项目表达骨架**：

> 基于 FastAPI 与 LangGraph 构建受控业务操作 Agent：模型负责意图与工具建议，后端负责策略校验、人工确认、Checkpoint 恢复、幂等执行与审计追踪。

将具体技术名、测试和结果替换为已完成版本中的真实事实。

## Version B：Java AI 应用版

**目标岗位**：Java 后端 AI 应用、Spring AI、智能业务系统。

**优先强调**：Java 后端能力、Spring AI、RAG、Tool Calling、多步任务、后端安全边界；Python 作为扩展 AI 工程能力。

**项目表达骨架**：

> 基于 Java 后端工程经验实现 Agent 业务能力，并以 Python 补充 FastAPI、原生 Tool Calling 与可恢复工作流，实现跨生态的受控 Agent 服务设计。

## Version C：AI 应用工程综合版

**目标岗位**：要求 Java/Python、模型接入、服务化和业务落地的综合型岗位。

**优先强调**：业务服务到 Agent 能力层的全链路；先放可证明的后端、Agent 安全与服务化能力，再列语言和框架。

## 版本选择规则

| JD 信号 | 优先版本 |
| --- | --- |
| LangGraph、Python、RAG、Agent Workflow 占主导 | A |
| Spring AI、Java 服务、业务系统占主导 | B |
| 同时要求后端、Python、模型接入和 Agent 落地 | C |

## 发布前核对

1. 每一个项目要点是否能链接到代码、设计、测试或演示？
2. 每个技术关键词是否能承受“为什么这样设计”的追问？
3. 是否把实验状态说成了线上事实？
4. 当前 JD 的关键词是否排在对应版本的前半页？
