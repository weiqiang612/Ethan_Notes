## 一、90 秒项目介绍

    ### 背景
    我实现了一个针对取消订单场景的受控业务操作 Agent。

    ### 问题
    业务写操作不能让模型直接执行，需要处理确认、权限、状态变化和失败恢复。

    ### 方案
    模型只提出工具调用建议；后端 Runtime 负责策略校验、参数与业务校验。高风险操作先生成草稿，用户确认后重新校验并通过幂等键执行；LangGraph 只用于需要暂停恢复的流程。

## 二、深挖问题库

每个问题必须链接到代码、ADR、测试或评测证据。

    ## Q：为什么不用普通 Chain？
    A：因为该流程需要暂停等待人工确认，并在之后以同一任务状态恢复；普通顺序调用需要自行实现状态持久化、恢复与状态迁移。这里仍保留简单读操作在原生 Runtime 中，不把所有请求都放入 Graph。
    证据：{链接}

    ## Q：为什么模型不能直接执行 Tool？
    A：模型输出只是建议。权限、白名单、参数 Schema、业务状态、确认和幂等都必须由可信后端控制。
    证据：{链接}

    ## Q：超时为什么不直接标失败？
    A：请求可能已到达下游而响应丢失。应进入 unknown，随后查询或对账，避免盲目重试导致重复写入。
    证据：{链接}

    ## Q：为什么 RAG 不用于订单状态？
    A：RAG 适合稳定、可引用的知识；订单状态是实时权威业务数据，应通过受控业务工具查询。
    证据：{链接}
