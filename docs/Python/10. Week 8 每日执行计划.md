# Week 8：法律案件研究工作流 Agent 作品化

> 前置条件：Week 3—7 的项目切片均有真实测试或演示证据。

## 周目标

收敛为可运行、可评测、可讲解的作品。它展示案件研究状态、Agent 工作流和可核验依据，不是法律 ChatBot 或律师服务。

    问题 / 脱敏材料 → 事实与证据整理 → 缺失信息澄清
    → 研究计划与受控检索 → 来源核验、引用绑定
    → 研究备忘录 → 等待补料 / 人工升级

## Day 50：范围冻结

v1 仅覆盖中国大陆劳动争议信息整理；不做替代律师、诉讼代理、胜诉预测、跨领域法律库或真实案件结论。只迁入已有验证证据的模块。

## Day 51：数据模型与架构

完成并解释 Case、Fact、Evidence、LegalIssue、Source、ResearchAction、ResearchMemo；说明模型建议、后端策略决策、工具执行三条边界，以及为何聊天记录不足以承担案件研究状态。

## Day 52：工作流与演示

至少演示：缺失事实追问；材料形成时间线和证据清单；带来源的研究备忘录；来源无法核验或事实不足的降级；用户补料后任务继续而非重新聊天。

## Day 53：评测报告

记录真实样本、命令、版本、通过/失败数与未覆盖风险。覆盖事实提取、研究动作、来源核验、引用忠实度、材料冲突、提示注入、安全降级和人工升级。

## Day 54—56：交付、表达与复盘

- 用脱敏样例完成干净环境验证，检查日志、Trace、容器层和 Git 无密钥或原始敏感材料；
- 只根据已实现能力撰写 README、简历表述和演示稿；
- 列出已证明/未证明能力；后续只选一个方向：扩展评测集、增加受控来源适配器，或评审一个开源 Agent Runtime。

## 完成定义

核心链路可演示，引用与状态可追溯，失败路径可解释，测试和评测可复现，并能诚实说明这是研究辅助系统而不是律师服务。
